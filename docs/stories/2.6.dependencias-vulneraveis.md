# Story 2.6 — Dependências vulneráveis

- **Épico:** E2 · **Sprint:** 3 (antecipada) · **Bloqueio:** 🟢 · **Status:** Concluída, com dívida registrada

## Resultado

**21 vulnerabilidades → 4.** A única de runtime com correção disponível foi resolvida.

| Antes | Depois |
|---|---|
| 16 high, 4 moderate, 1 low | 1 high, 3 moderate |

## O que foi feito

1. **`npm audit fix`** (sem `--force`): resolveu 16 vulnerabilidades transitivas sem alterar
   uma linha do `package.json`. `react-router` caiu de high para moderate no caminho.

2. **`xlsx` migrado para a distribuição oficial da SheetJS.** Esta era a mais séria de runtime:
   prototype pollution e ReDoS, `fixAvailable: false`, numa biblioteca que faz parse de
   planilhas enviadas por usuário. A SheetJS saiu do npm; a versão publicada lá está congelada
   em 0.18.5 e não recebe correção. Agora:

   ```json
   "xlsx": "https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz"
   ```

   API compatível — `AdminAtivosUpload.tsx` e `AdminLimites.tsx` não precisaram mudar.

## Dívida registrada, com análise de exposição

| Pacote | Sev | Por que não foi corrigido | Exposição real |
|---|---|---|---|
| `vite` | high | Correção exige major (v7). É dependência de **build**. | **Nenhuma em produção**: o CVE afeta o dev server servindo arquivos indevidos. O deploy publica estáticos atrás do nginx — não há dev server rodando. |
| `esbuild` | moderate | Transitiva do vite, mesmo caso | Nenhuma em produção |
| `react-router-dom` | moderate | Correção exige migrar v6 → **v7** (major) | Baixa: o CVE é redirect externo por caminho não confiável. O app não constrói rota a partir de entrada do usuário — todo `navigate()` aponta para rota fixa. |

**Recomendação:** a migração do React Router para v7 merece story própria, com teste de
navegação, e não deve ser embutida num `audit fix`. Pela análise acima, não é urgente.

## Ponto de atenção para o deploy

O `xlsx` agora vem de `cdn.sheetjs.com`. **O ambiente de build precisa alcançar esse host.**
Se o build do Dokploy for restrito, espelhe o pacote num registro interno. Registrado também
no `deploy/README.md`.

`tsc --noEmit` sem erros e `npm run build` OK após cada alteração.
