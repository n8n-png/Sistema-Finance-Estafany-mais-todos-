# Story 2.4 — Corrigir o fluxo de redefinição de senha

- **Épico:** E2 · **Sprint:** 3 (antecipada) · **Bloqueio:** 🟢 · **Status:** Concluída

## O problema era pior do que o relatado

A Lavínia descreveu na reunião: *"a redefinição de senha dele mesmo é um link que clica e a
hora que você clica nesse link, a página abre"*. Lendo o código, a causa apareceu — e o
impacto é maior do que "não tem validação".

O link de "Esqueci minha senha" volta para `/auth` **já com uma sessão válida** no fragmento
da URL (é assim que o Supabase entrega a recuperação). O efeito da tela via `user` preenchido
e redirecionava direto para a home:

```tsx
useEffect(() => {
  if (!loading && user) navigate("/", { replace: true });
}, [user, loading, navigate]);
```

Ou seja: **o link do e-mail funcionava como login automático e a senha nunca era trocada.**
Consequências:

1. Quem tivesse acesso à caixa de entrada entrava na conta sem saber a senha.
2. A senha antiga continuava valendo — não havia rotação nenhuma.
3. O link de recuperação, que fica no histórico do e-mail, seguia sendo uma porta de entrada.

## Critérios de aceitação

1. Chegando por link de recuperação, a navegação fica **bloqueada** até que uma nova senha
   seja definida — detectado por `type=recovery` na URL e pelo evento `PASSWORD_RECOVERY`.
2. Formulário de nova senha com confirmação.
3. Após a troca, a sessão aberta pelo link é **encerrada** e o usuário entra com a senha nova.
   O acesso passa a depender de saber a senha, não de ter recebido o e-mail.
4. Política de senha unificada: mínimo 10 caracteres, com maiúscula, minúscula e número
   (era 6, sem exigência de composição).
5. A mesma política vale na troca manual (`ChangePasswordButton`).
6. "Esqueci minha senha" responde igual existindo ou não a conta — não entrega a lista de
   quem tem acesso ao sistema.

## Observações

O limite de 72 caracteres não é escolha nossa: é o máximo que o bcrypt considera — o que passa
disso é silenciosamente ignorado.

Esta story reduz o risco, mas **não substitui o login Google** (Story 2.3), que continua sendo
o destino para o time interno.
